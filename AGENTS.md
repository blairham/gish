# AGENTS.md — gish

Guidance for AI coding agents (Claude Code, Cursor, Copilot, Codex, OpenCode, …) working in this repository. This is the **cross-tool single source of truth** — `CLAUDE.md` imports it.

## Project Overview

**gish** is a new interactive shell: zsh's interactive experience, bash's ubiquity as scripting substrate, and a native, contract-first plugin system. Cross-platform (macOS, Linux, Windows), written in Go, shipped as a single static binary named `gish`.

The name rhymes with fish/wish, and was chosen after an exhaustive availability sweep (~55 candidates) found every other 3–4 letter `-sh` name claimed, most by existing shells. It had a bash-style expansion — "gRPC Interactive SHell" — and that **backronym is retired** (#169): the research falsified the premise behind it. nushell already ships out-of-process plugins in any language, and every fish-parity UX feature is replicable as a zsh or bash add-on (ble.sh does fish-grade highlighting and autosuggestion *in pure bash*). A plugin architecture is not why anyone switches shells.

What is defensible is narrower and more durable: **bash compatibility**, which was the historical gate — fish's disqualifier for the Apple default was sh-incompatibility, not licensing — and **the exec path**: sandbox profiles, deadlines, parse-tree footgun detection, secret-free history. That is the one layer an add-on provably cannot own, because an add-on lives inside the shell it extends and does not control execution. See docs/strategy.md, which also records the three numbers we were repeating that turned out to be wrong.

The design bet is a **two-tier plugin system**:

- **Tier 1 — script plugins**: the existing zsh plugin ecosystem (zi/zinit/oh-my-zsh style), run in-process against a *pattern-compat* layer — aliases, exports, PATH edits, precmd/preexec, completion registration. Demoted from adoption story to **migration escape hatch** (#105): the adoption story is fish-grade defaults + bash paste-compat + the native stack; a switcher's must-have plugin shouldn't block the move, but the .zshrc pile is what people are fleeing. No compsys emulation, no zle shims beyond the trivial, no zsh dialect on the critical path.
- **Tier 2 — native gRPC plugins**: resident subprocesses over hashicorp/go-plugin with a versioned protobuf API (`proto/gish/plugin/v1`). Completion providers, prompt segments, history backends. This tier is the differentiator: plugins get a real contract instead of poking shell internals, and can be written in any language. Precedent: gitstatusd and carapace already prove out-of-process is how fast shell tooling works.

Non-negotiable latency rule for tier 2: every host→plugin call carries a deadline; a slow plugin degrades (stale segment, missing completions), it never blocks a keystroke or the prompt.

**Status: interactive core in progress (M2).** Scripting runs on `mvdan.cc/sh` (POSIX/bash parse + interp). Interactive terminals get the raw-mode line editor (`internal/editor`): emacs keymap, kill ring, undo, grapheme-aware multi-line editing, diff-based inline rendering, and byte-level type-ahead preservation across commands. Signal posture is in place (#3): the interactive shell survives SIGINT/SIGQUIT — Ctrl-C interrupts the foreground command (children via the kernel, builtin loops via context cancellation) and never the shell. History is in (#4): metadata-rich JSONL at `$XDG_DATA_HOME/gish/history.jsonl` (mirrors the plugin proto's HistoryEntry), prefix-aware up/down, ctrl-r incremental search, ignorespace + consecutive-dedup + secret scrubbing (#10: gitleaks-style rules in internal/history/scrub.go — matching commands never reach disk, with a notice). Stored entries fan out asynchronously to HistoryBackend plugins (fire-and-forget, deadline-bounded). Startup config is in (#6): the rc file (`$GISH_RC` → `$XDG_CONFIG_HOME/gish/gishrc` → `~/.gishrc`, first hit wins) runs in the session runner. `GISH_PROMPT`/`GISH_PROMPT_CONT` remain the manual override but are **no longer a separate pipeline** (#109): they are the `literal` theme inside the theme engine, so plain/p10k/starship/plugin/manual all render through one dispatch (`themeName` resolves precedence: manual > NO_COLOR-forced plain > GISH_THEME). The escape set is frozen and zsh-spelled — `%n`/`%u`, `%m`/`%h`, `%~`/`%w`, `%W`, `%d`, `%?`, `%#`, `%p{id}`, `%%` — with unknown escapes passing through. Job control is in (#5): each command line runs in its own process group with terminal handoff (`SysProcAttr.Foreground`, race-free), stops observed via `Wait4(WUNTRACED)`, and jobs/fg/bg as gish builtins routed through the CallHandler rewrite. **The M2 interactive core is complete.** M3 has begun: the plugin host (#7) is live — discovery from `$XDG_DATA_HOME/gish/plugins`, lazy resident launch, Describe-driven capability wiring, deadline constants from docs/plugins.md, crash healing with exponential backoff, and the `plugins` builtin for inspection. Plugin configuration is a **declarative manifest, not ice modifiers** (#108, internal/manifest + internal/repl/plugincmd.go): `$XDG_CONFIG_HOME/gish/plugins.toml` holds source/kind/pin/lazy entries, `plugin add|remove|pin|enable|disable|update` edits it (config-style: writes the file *and* takes effect), lazy entries defer through a CallHandler that sources the payload on first use of their trigger command, and `zi migrate` imports existing installs. The zi engine remains the implementation and `zi` still works behind a one-time deprecation notice; ice syntax is documented only for migration. The zi plugin manager (#23) is in: zi-go's engine ported to internal/plugmgr behind the replaceable Manager contract, driven by the `zi` builtin through the CallHandler — a load becomes `source <payload>` in the live shell (the upstream zsh shim is gone). Existing Zi syntax and ~/.zi-go layouts carry over. The flagship gish-git plugin (#8) ships in cmd/gish-git — a gitstatusd-class prompt segment (fsnotify invalidation, background refresh, stale-on-miss) consumed via the `%p{git}` prompt escape. Completion v1 (#32, M4) is in: Tab completes command names (PATH+builtins+functions, cached) and file paths (core providers in internal/complete), merges CompletionProvider plugins behind the 80ms budget, inserts escaped values (host owns quoting), and lists candidates below the edit line when ambiguous. The carapace bridge (#9, cmd/gish-carapace) plugs ~1,000 CLIs into that socket by shelling out to the user's carapace binary (`export` JSON), guarded by its supported-command list — no carapace installed means empty results, never errors. CommandProvider (#11) is live: plugins register commands (reserved builtin names rejected, PATH shadowed, streamed I/O, no raw-TTY handover in v1) routed by an mtime-cached command index — warm sessions know plugin commands without launching anything. Startup is guarded (#37): ~6ms warm to first prompt, CI regression gate in cmd/gish/startup_test.go (`make bench-startup`); prompt-segment discovery warms in the background and the first render waits only within its 50ms budget — plugin launches never block first paint. Fish parity is in (#38/#39): parser-driven syntax highlighting (real parse tree — unknown commands red, strings/expansions/comments styled, first-word fallback on mid-edit parse errors) and history ghost-text autosuggestions (Right/End accepts), both skipped under NO_COLOR/dumb terminals. M5 quick wins: live cross-session history (#40: lookups reload the file tail, own-session entries skipped, partial-line tolerant), Damerau did-you-mean suggestions on command-not-found (#42), native brew shellenv at startup (#44: stat/string only, no subprocess), and first-class starship (#45: GISH_THEME=starship renders via the binary, budgeted + stale fallback, hint-never-autoswitch). Login-shell correctness (#41): -l or a dash-prefixed argv[0] sources /etc/profile then ~/.gish_profile|~/.profile ($GISH_PROFILE overrides for tests); the -c/script path is POSIX-clean and prompt-free, pinned by the compat suite in cmd/gish/compat_test.go. The prompt starts naked: the out-of-box default is the stock zsh/bash shape (`user@host dir %`), and themes are explicit opt-ins — GISH_THEME=p10k selects the **native powerlevel10k port** (internal/p10k, see below), GISH_THEME=gish the original segment-knob theme (#26, internal/repl/theme.go: smart path, git segment, .tool-versions pins, jobs/duration/exit — GISH_THEME_* configures this one), GISH_THEME=starship the starship renderer, and any manual GISH_PROMPT always wins; NO_COLOR and TERM=dumb force naked regardless. **The p10k theme is a port of powerlevel10k's behavior into Go, never a zsh shim** (internal/p10k, docs/p10k.md): configuration is modeled the way upstream models it — a flat parameter namespace resolved through the same three-step fallback chain (SEGMENT_STATE_KEY → SEGMENT_KEY → KEY) — which is what lets the six presets (lean, classic, rainbow, pure, lean-8colors, robbyrussell) be *data* over one layout algorithm rather than six renderers. Segments return color as `Span`s rather than pre-escaped strings, because a segment that bakes in its own reset also clears the background beneath it (that is how a powerline preset gets holes in its ribbon). ~50 segments are implemented and **none of them fork**: version managers read their pin files, kubecontext reads one top-level YAML scalar by hand, and a per-render memo backs the directory walk so twelve segments share one walk — that rule is where the speed comes from, and the unimplemented segments are exactly the ones needing a subprocess or a network call (battery, ram, load, public_ip, taskwarrior, the `*_version` family). Config layers preset → `$XDG_CONFIG_HOME/gish/p10k.conf` (mtime-cached, so edits land on the next prompt) → `POWERLEVEL9K_*` set in the session. The `p10k` builtin is the surface: `configure` (huh wizard, asks the font question rather than sniffing it, writes a complete resolved config), `import` (the **only** place in the codebase that reads zsh — offline, once; takes 304/310 settings from a real 1720-line .p10k.zsh and reports by name the ones whose value is shell code, like the stock `my_git_formatter`), `show`, `preset`, `list`. Transient prompt is in (editor `Config.Transient` swaps the prompt for the final render); `same-dir` necessarily inverts upstream's rule since the trim happens before the command runs. **Instant prompt is deliberately not implemented**: gish resolves a full p10k prompt in ~7ms (cmd/gish/startup_p10k_test.go gates it), the same as the naked prompt, so there is nothing to cache ahead of it — the setting is accepted and `p10k show` explains it. Measured head-to-head in docs/bench.md: gish 5.6ms vs zsh+powerlevel10k 86.3ms to first prompt. cmd/gish-p10k serves the same engine over the tier-2 ThemeProvider contract as `p10k-<preset>` — #30's first real implementation, live round trip at 129µs — but the shell itself renders in-process, since its own prompt should not pay a round trip. Blocks stages 3 and 4 are in (#99, internal/blocks + internal/repl/blockscmd.go): a history entry gains a `block` reference and the output lives under $XDG_DATA_HOME/gish/blocks, content-addressed — identical output costs one file and a ref cannot escape its directory. Retention is age, then count, then total bytes, with bytes last so a size cap never evicts recent output to keep old output. The #10 rules run **as output is written**, and the posture deliberately differs from a command line: output is **redacted, not rejected**, because dropping a 200KB build log over one echoed token destroys exactly what the user wanted, while dropping a command line is proportionate since there the secret essentially *is* the command; SecretReason and RedactOutput now sit side by side and which applies is a property of what is written, not who writes it. The `blocks` builtin lists, shows and **searches by what a command printed** — the thing history structurally cannot do — and a shown block reports truncation and redaction rather than presenting a partial or doctored log as whole. Bare `blocks` on a terminal opens the #100 picker over the same commands while `blocks list` and every headless path keep the plain listing — the picker is a presentation layer, not the only way in — and since the picker returns command *text*, selection resolves to the **most recent** match (picking `make build` means the run you just did). Ctrl-R shows a line of captured output beside each command (#99 complete): the first line that looks like a failure, else the first non-blank one — a command that greets before it works would otherwise preview "Cloning into…" rather than the error under it — with colour stripped since the picker renders it dim. Bounded to the newest 150 entries and 4KB each, because the picker builds every row before painting and a read per row would be paid on every Ctrl-R; a row with no preview is normal, since capture is opt-in and neither stderr nor builtin output is captured. Blocks stage 2 is in (#99, internal/capture + internal/jobs): opt-in output capture behind `config blocks on`, off by default. The design corrects what docs/blocks.md predicted, and the correction is the reason it was tractable — the doc assumed a PTY meant gish must relay signals and interleave with the race-sensitive foreground handoff, which is true only when the PTY becomes the child's **controlling terminal** (script(1)'s shape). Here the child gets the PTY for **stdout only**; stdin, stderr and the controlling terminal are untouched, so Ctrl-C, Ctrl-Z, SIGWINCH and the pre-exec foreground-group handoff keep working *because nothing about them changed* — job control preserved by construction, not reimplemented. Probed before building: isatty(stdout)=yes, size queries correct, ctty still the real tty. gish owns only the PTY's window size (SIGWINCH via a second signal subscriber, since the editor's own only runs while it reads) and the copy loop, which writes to the screen *first* and records second — capture must never be why output is late. The ring keeps the tail, not the head, and reports truncation so a partial log never reads as complete. **stderr is deliberately not captured, and that was measured**: the first cut captured it too, and `less` then painted a screen but never entered raw mode — full-screen programs do terminal control on fd 2, so they configured the pty while the real terminal stayed cooked, and keystrokes meant for the pager echoed onto the shell's line. Leaving stderr alone fixes it (`less` and `vim` verified under a pty); the honest cost is that a command's errors are not captured, which is the price of "programs behave exactly as today". **Builtins are not captured either** — capture substitutes an external child's stdout and a builtin never becomes a child, so `printf` goes straight to the terminal while `/bin/echo` is captured; closing that hole means routing the whole line's stdout through the pty, which is bigger than stage 2. Redirected output is never captured: `cmd > file` already has somewhere to go, and a PTY would both steal it and mangle it (the line discipline translates \n to \r\n — verified by byte count). Close() closes the slave *before* draining, since the master reports EOF only once every slave fd is gone. Stages 3–4 (block records with #10 scrubbing, the `blocks` builtin) remain. OSC 52 clipboard is in (#140, internal/term/clipboard.go + internal/repl/clip.go): `… | clip` sets the clipboard of the terminal the human is sitting at rather than the machine the shell runs on, so it is the one clipboard path that works unchanged over ssh — no X11 forwarding, no reverse tunnel to pbcopy, nothing installed on the far side. **Set only, never query**: OSC 52's read form would let a shell exfiltrate whatever was last copied, which is exactly why terminals gate the sequence, so it is simply not implemented rather than implemented and discouraged (a test records that decision). tmux and screen eat unrecognized sequences, so the payload is re-framed per multiplexer — tmux needs DCS tmux + every inner ESC doubled + `allow-passthrough on`; screen needs plain DCS — detected via $TMUX/$STY because there is nothing else to go on. Oversized payloads are refused, not truncated: terminals cap around 74–100KB and a truncated base64 blob decodes to garbage. The escape goes to os.Stdout, never hc.Stdout, which in a pipeline is the next command's stdin. Gated by the usual real-TTY + color-willing check, so scripts get a silent no-op; doctor names the terminal and, for the ones shipping it disabled, the setting. OSC 133 semantic marks ship (#99 stage 1, internal/repl/semantic.go): every command emits prompt-start/prompt-end/output-start/done-with-status, so kitty, WezTerm, Ghostty, iTerm2, and VS Code give gish users scroll-to-prompt, select-output, and click-to-rerun *today* without gish becoming a terminal; doctor names the terminal and what it supports, GISH_SEMANTIC_MARKS=off opts out. The A/B marks wrap the prompt *string* rather than the render call — the renderer already treats escapes as zero-width and atomic, so they survive redraws, wrapping, and multi-line prompts. Output capture is deliberately **not** shipped: a foreground child gets the real terminal fds and its process group owns the terminal, so capture means a pipe (breaks isatty — kills paging and color) or a PTY (preserves behavior but must take over window-size and signal forwarding around a race-sensitive handoff). docs/blocks.md records the decision — PTY, opt-in, foreground-only — and the staged plan, so it is not re-litigated. History sync is in (#97, cmd/gish-atuin + internal/repl/histsearch.go): the HistoryBackend contract's read half, which had never been wired — Append fanned out (fanout.go) but nothing queried backends for ctrl-r. searchBackends asks every backend concurrently inside one 100ms DefaultHistorySearchBudget (two slow backends cost one budget, not two), drains partial batches, and mergeHistory folds results in behind the local ones: **local wins every tie** — a backend's copy of the same command carries another machine's cwd and clock, and showing that would be a quiet lie about where the command ran — local entries are never evicted by the cap, and rows the local store never had are labeled `synced` in the picker so they don't read as a bug. gish-atuin is the reference backend and is deliberately a **bridge, not a reimplementation**: atuin's opt-in, self-hostable, E2EE posture is the whole reason it's trusted, and reimplementing sync would inherit none of it. Two details read off atuin's own clap definitions rather than guessed, both of which fail silently: `history end --duration` is **nanoseconds** while the proto is milliseconds, and commands travel via ATUIN_COMMAND_LINE (`--command-from-env`) with results returned `--print0`-separated, because shell history is exactly the corpus full of newlines and quotes. `--filter-mode global` because atuin's configured default may scope to one host, which defeats the point. No atuin installed = empty results, never errors (the gish-carapace posture); doctor catches the silent case where the plugin is installed but atuin is not. `gish ssh` is in (#98, internal/remote + cmd/gish/ssh.go): the answer to the most-cited blocker to switching shells — the box you only have ssh to. One multiplexed ssh connection (ControlMaster, one auth), one 2s-bounded probe (`uname -sm`, a writable *and executable* dir — /tmp is noexec on CIS-hardened hosts, so the probe writes a script, chmods it, and runs it — hash tool, already-present check), then `cat > file.partial` (not scp/sftp, which hardened boxes disable; ssh -C does the compression so no remote gzip is needed), verify sha256, rename, and `ssh -t host 'exec <path> --remote-session --rc <path>'`. The binary is content-addressed, which buys free upgrades, truncation detection, and safety from a co-tenant on a shared box — the threat model is explicitly *not* a rooted host. **Never installs**: no chsh, no remote dotfiles, no daemon, and `ssh` is never shadowed (auto-hijacking it drops executables on servers people don't own — FIM alerts, change control). Config travels as a hash-named 0600 rc of GISH_* display settings passed *as a path* (argv is world-readable via /proc; SendEnv is restricted by AcceptEnv); history, credentials, and plugins do not travel. Cross-platform builds are **not downloaded** (#112's line): $XDG_CACHE_HOME/gish/remote-bin/<os>-<arch>/gish, with the exact `go build` command in the error. Every failure lands in plain ssh with one line on stderr. `config ssh.bring ask|always|never` (ask once per host, remembered in ssh-trust state that resets to ask when corrupt), `--ephemeral`, `--forget`, `--uninstall`, and a README dropped beside the binary so a sysadmin shrugs instead of filing a ticket. The Transport interface (Run/Interactive/Close) is load-bearing twice over: kubectl/docker exec are the same problem, and the local `sh` transport makes the whole failure matrix testable with no ssh and no network. Terminfo is deliberately not pushed — internal/term is escape-sequence based end to end. docs/ssh.md is the reference; OSC-52 clipboard split to #140. The selection primitive is in (#100, internal/ui/fuzzy.go + picker.go): one bubbletea picker with an in-tree fzf-shaped fuzzy matcher (subsequence, scoring consecutive runs / word starts / early matches), reused by Ctrl-R and the `pick` builtin. Ctrl-R is now a full-screen picker over history showing cwd, age, duration, and exit status per row (history.RecentEntries supplies the metadata the JSONL store always had), falling back to the incremental search when the terminal cannot host a TUI — including when it reports an unusable size, which would otherwise spin the renderer. `… | pick [-m]` is the same widget as a pipeline primitive, reading keys from /dev/tty since stdin is the candidate list. The editor's external-edit machinery generalized into a **handover**: any full-screen program (an $EDITOR, a picker) gets raw mode suspended and the decoder stopped, then resumed — that seam is how future full-screen surfaces should take the terminal. Muscle-memory parity is in (#96, internal/editor/readline.go + internal/repl/histexpand.go): the readline commands whose absence has documented cases of people abandoning a shell — Alt-. / Alt-_ yank-last-arg with repeat-to-cycle (wrapping at the oldest, replacing the prior insertion), Alt-# comment-and-accept, Ctrl-T transpose, Ctrl-O operate-and-get-next (queues the next history entry into the following prompt via editor.Preload), and Ctrl-X Ctrl-E edit-in-$EDITOR (ReadCommand splits into decoder sessions so raw mode and the decoder are suspended around the child — VISUAL/EDITOR from the session first, then the environment). History expansion runs on the raw interactive line before parsing: !!, !$, !^, !:N, !:N-M, !prefix, ^old^new, echoed bash-style, never firing inside single quotes or on `! `/`!=`/`!(`. Tab expands $VAR/${VAR}/~ under the cursor (the zsh behavior fish converts miss). Ctrl-R cycling and Ctrl-G restore-line already matched readline. Numeric arguments (Alt-4 Ctrl-D) are the one deliberate gap, split to #116. Footgun diagnostics (#46, internal/repl/lint.go): the parsed buffer is checked per keystroke — unquoted expansion under destructive commands, cd sequenced (not &&-chained) before a destructive command, unquoted expansion in [ ], useless cat, self-truncating redirects — and warnings render as dim caution lines below the edit line via the editor's Diagnose hook; multi-line buffers additionally get a budget-bounded shellcheck pass on Enter when installed. Advisory only, never blocking; GISH_LINT=on|native|off. The `config` command (internal/repl/config.go, groundwork for #28) sets and persists settings in one step — `config theme starship` validates the value, rewrites the assignment in the rc file (creating the XDG one when none exists), and goes live via a CallHandler rewrite to `eval`; settings: theme (plain|p10k|starship), lint (on|native|off), prompt (free-form). Theme engine v2's first slice (#28): the themed first line is segment-driven — GISH_THEME_SEGMENTS picks and orders segments (built-ins dir git pins jobs duration exit, plus any %p{id} plugin segment by its id), GISH_THEME_COLOR_<ID> overrides a segment's color (named palette or raw SGR params), and config grew dotted keys: `config theme.git off` toggles one segment (built-ins re-slot in default order, plugin ids append), `config theme.segments 'dir git exit'` sets the list, `config theme.color.dir cyan` overrides (`default` clears), `config theme.lines 1` drops the two-line frame for an inline arrow, `config theme.sep powerline` swaps the two-space separator for a dim nerd-font chevron; bad values degrade to defaults, never break the prompt. `config theme` on a terminal is the p10k-configure-style wizard (internal/repl/wizard.go): ask each knob with Enter-keeps-current, show the powerline glyph and let the human judge the font (ask-don't-detect), preview the chosen layout, and persist only on the final confirmation — one rc write per changed variable, one eval for the live assignments; piped stdin keeps the plain show so scripts never hang. Right prompt (#28): GISH_THEME_RPROMPT holds right-side segment ids (same vocabulary as the left, plus the `time` built-in that lives right by convention), rendered by the editor one column short of the right edge, zsh-style — it hides whenever the typed line would reach it and never wraps; `config theme.rprompt 'time'` sets it, empty clears, manual GISH_PROMPT/plain/starship/NO_COLOR all mean no right prompt. Rounding out #28: `config theme.frame off` keeps two lines but drops the ╭─/╰─ corners (bare arrow — the spaceship shape), and `config theme.preset spaceship|p10k` applies a whole look from the same knobs — each preset writes the full variable set (theme, segments, rprompt, lines, sep, frame, section colors) so switching never leaves a stale knob behind; the wizard asks the frame question on the two-line path. Themes are pluggable (#30): the v1 protos grew a ThemeProvider service (theme.proto — Themes enumeration, RenderPrompt over a full PromptContext, rprompt in the response) with CAPABILITY_THEME and host wiring; GISH_THEME resolves a built-in name first (plain/p10k/starship, now peers in a builtinThemes registry behind one render-the-triple signature — reserved, unclaimable by plugins), else a discovered plugin theme by declared name (internal/repl/themeplugin.go: background warm-up, budget-bounded RenderPrompt, stale prompt-set fallback), else the native p10k-class theme — an asked-for-but-unserved theme never silently goes naked, and doctor says why. gish-direnv is in (#137, cmd/gish-direnv): real direnv behind the EnvProvider contract, on the #112 line — delegate .envrc evaluation and the whole stdlib (`use nix`, `layout python`, `source_up`), own the cd moment (no `direnv hook`), the approval UX, and apply/revert. Three findings from testing against real direnv rather than assuming, each of which would have shipped a silent bug: (1) `direnv export json` fails *identically* (exit 1, prose on stderr) for blocked, denied, and broken-.envrc — three states needing opposite responses — so the plugin keys on `direnv status --json`'s enum (allowed 0 / blocked 1 / denied 2 / foundRC null) before exporting; (2) direnv reports **symlink-resolved** paths, so on macOS every /tmp and /var path returns as /private/… and, since #12 compares for_dir to cwd as strings, returning it verbatim would have discarded every proposal on half the target platform — rcDir maps it back into the caller's namespace; (3) DIRENV_* bookkeeping is stripped, because the host's 6-key allowlist never sends it back, so direnv runs stateless and gish owns revert. The two-trust-model problem is solved by an additive `EnvProvider.Allow` RPC (frozen-additive permits new RPCs; no version bump): `trust allow` tells the plugin, which runs `direnv allow`, so one gesture satisfies both — safe only because both key on content, so editing an .envrc re-blocks direnv *and* changes gish's diff hash and they re-prompt together. Best effort: a plugin that cannot record the approval does not block it (gish's record is authoritative for gish) but the user is told. Tests run against the user's real direnv and skip when absent — a hand-written fake would have encoded exactly the assumptions that were wrong. EnvProvider is live (#12, env.proto + internal/repl/envdiff.go): on directory change an env plugin proposes a direnv-class diff {for_dir, set, unset}; the trust model is host-enforced — nothing applies without `trust allow`, which records (plugin, for_dir, diff-hash) in $XDG_DATA_HOME/gish/env-trust.json (internal/envtrust, write-then-rename, corrupt file disables the feature rather than resetting trust); a changed diff re-pends with a fresh notice (edit-reprompts), deny-listed vars (LD_*/DYLD_*, IFS, ENV/BASH_ENV, GISH_*) are stripped before a proposal exists, PATH is settable only through the visible allow flow, requests carry the allowlisted env subset, for_dir must be cwd or an ancestor, and applied diffs snapshot every touched variable and revert when the shell leaves the subtree; `trust` / `trust allow` / `trust revoke [dir]` is the user surface (CallHandler builtin), EnvDiff is budget-bounded at 100ms (miss = retry next change), and doctor checks the trust file. ShellEvents is designed but not served (#83, proto/gish/plugin/v1/events.proto + docs/events.md): the contract for event-triggered automations — dir change, command done, file change, session end — is defined and CAPABILITY_EVENTS allocated, with no host wiring yet, deliberately in that order because a plugin contract is far harder to change once plugins exist. It is the one service that inverts the usual direction (the plugin is told things and may speak unprompted), so three rules are structural rather than advisory: **no exec channel ever** — Proposal has no field that causes execution, suggested_command lands in the editor buffer as data with the host owning quoting (#111's host-agents line, #20's preview posture); **the host never blocks on a subscriber** — which forced the bidi `Subscribe(stream ShellEvent) returns (stream Proposal)` shape, since go-plugin makes the host the gRPC client and a request/response per event would make every cd wait on a plugin; and **events carry allowlisted scrub-safe data only** — COMMAND_DONE sends the command's first word, never its argument list, because that is where tokens and private paths live. Proposals carry event_seq so a suggestion for the directory you just left gets dropped. ## Architecture invariants

Read these before touching `pluginhost` or the protos.

- **`proto/gish/plugin/v1` is frozen-additive**: new fields and new RPCs are fine; renames, type changes, and removals are not. Breaking changes mean a `v2` package and a `Handshake.ProtocolVersion` bump.
- **Deadlines are the host's job**: `pluginhost` attaches a deadline to every outbound call (prompt segments default to a 50ms budget; segments can declare their own via `SegmentDescriptor.budget_ms`). Plugin responses that miss the deadline are dropped or served stale — never awaited.
- **Plugins are resident**: launched lazily on first use, kept alive for the session. Never spawn-per-call.
- **Environment is allowlisted**: completion/prompt requests carry a filtered env map, never the full environment.
- **The shell owns history**: a HistoryBackend plugin observes and serves search; the local history file works with zero plugins installed.
- **Windows is a target, not a port — sequenced to v1.x (#110)**: keep the invariants that make the port a resume rather than a restart (no unix-socket-only assumptions — go-plugin falls back to TCP loopback; PATHEXT-aware executable checks; USERPROFILE beside HOME in tests; the windows-latest CI job gates every PR). Native interactive work (ConPTY, job objects, installer — #87/#89) is deliberately paused until after a v1 that wins on macOS/Linux; WSL2 is the documented Windows story meanwhile.

## Code Conventions

- **Go version**: `go.mod`'s `go` directive and `.tool-versions`' `golang` pin must match **exactly** — enforced by the `check-go-version-sync` pre-commit hook from [blairham/pre-commit-hooks](https://github.com/blairham/pre-commit-hooks). `go.mod` is authoritative; run `make sync` to bring `.tool-versions` back in line. CI pins the minor line (`GO_VERSION: "1.26"`)
- **Formatter**: gofumpt via `go tool` (pinned in go.mod's `tool` block alongside golangci-lint). Formatting is applied at commit time by the `golangci-lint-fmt` hook, driven by `.golangci.yml`
- **Linter**: golangci-lint v2, config in `.golangci.yml` (`pkg/pluginapi` is excluded — it's generated)
- **Imports**: grouped by goimports with local prefix `github.com/blairham/gish` — local imports get their own trailing group
- **Generated code**: `pkg/pluginapi` comes from `make proto` only; regenerate rather than edit, and commit the output so builds don't require protoc
- **Exit codes**: `errors.As` with `interp.ExitStatus` distinguishes a script's exit status (propagated as the process exit code) from real gish errors (stderr + exit 1)
- **Commits/PRs**: no AI-attribution trailers — do not add `Co-Authored-By: Claude`, "Generated with Claude Code", or similar to commit messages or PR bodies

## Bash compatibility

`docs/compat.md` is the published scoreboard (#101): a curated corpus of
real-world snippets (`internal/compat`) run **differentially** — the same
script through the machine's real bash and through `gish -c`, comparing
combined output and exit status. bash is the oracle; nothing encodes what
we think bash ought to do. `make compat` regenerates the doc from a live
run; `make compat-check` is the CI gate that refuses a lower pass count

fall without a regression — that is the point. Substrate gaps go upstream

an open decision (#120), not a bug.

## Builtins

Every builtin gish claims is exercised against real bash
(`cmd/gish/builtins_matrix_test.go`) or, where bash has no equivalent,
against its own observable behavior (`nativebuiltins_test.go`). The two
matrices check each other: a name that is intercepted without a case, or
a case for something nothing intercepts, fails.

The rule that produced most of the fixes: **a name `interp.IsBuiltin`
recognizes never reaches the exec seam**, so leaving one unimplemented
does not fall through to the program on the machine — it shadows it, and
answers "unsupported builtin". That is worse than absent. `printf` (no
precision, no `%f %e %g %X %q`), `kill`, `umask` and `times` were all in
that state and are now native, reached by renaming the call at the
CallHandler so it arrives at the ExecHandler where a builtin can return
a real exit status. Returning a status from the CallHandler is not an
option: the interpreter treats a CallHandler error as *fatal*, so
`kill somepid || echo nope` would take the shell down.

Two names are deliberately partial, and say so rather than failing
blankly:

- **`fc`** implements the listing half (`fc -l`). The editing forms
  re-execute a command, which belongs to the REPL's run loop rather than
  to a builtin.
- **`newgrp`** is not provided. It changes the real group id and re-execs
  the shell — closer to `su` than to a builtin, and the one name here
  where a half-implementation would be a security problem rather than an
  inconvenience. `/usr/bin/newgrp` is one path away, and the builtin says
  so.

## Benchmarks

`docs/bench.md` is the published performance claim (#102), generated by
`make bench` from `internal/bench`. Startup: every shell launched under a
real pty with its prompt overridden to one shared marker, so "first
prompt" is the same event everywhere; medians *and* best-of are printed,
missing shells are reported rather than dropped, and each row states what
it includes. Keystroke latency is measured end to end — byte into the pty,
clock stops when the repaint comes out — so decode, highlight, suggestion
lookup, lint, and render are all inside the number; that is the answer to
"is there RPC in the keystroke path?". Timing is never a CI gate (a loaded
runner would fail an honest shell); #37's budget test remains the
gish-vs-gish guard. Two harness rules learned the hard way: `SetReadDeadline`
is unsupported on ptys, so pty reads must be a goroutine plus select, and
benchmarks must start in a neutral cwd or they measure the measuring
directory. Both rules bind `cmd/gish/startup_test.go` too: a bare pty
read there once turned a single missed prompt marker into a 10-minute CI
timeout with no evidence, so the gate reads via goroutine plus select and
fails with the bytes it did see. Its prompt marker is the OSC 133;B mark
(#99) — the exact "prompt ended" signal — with the glyph markers kept as
the `GISH_SEMANTIC_MARKS=off` fallback.
