# AGENTS.md — gish

Guidance for AI coding agents (Claude Code, Cursor, Copilot, Codex, OpenCode, …) working in this repository. This is the **cross-tool single source of truth** — `CLAUDE.md` imports it.

## Project Overview

**gish** is a new interactive shell: zsh's interactive experience, bash's ubiquity as scripting substrate, and a native, contract-first plugin system. Cross-platform (macOS, Linux, Windows), written in Go, shipped as a single static binary named `gish`.

The name expands bash-style: **gish = gRPC Interactive SHell** — the tier-2 plugin system is the differentiator, so it's in the name, the way bash's expansion carries its own origin story. Rhymes with fish/wish; chosen after an exhaustive availability sweep (~55 candidates) found every other 3–4 letter `-sh` name claimed, most by existing shells.

The design bet is a **two-tier plugin system**:

- **Tier 1 — script plugins**: the existing zsh plugin ecosystem (zi/zinit/oh-my-zsh style), run in-process against a *pattern-compat* layer — aliases, exports, PATH edits, precmd/preexec, completion registration. Demoted from adoption story to **migration escape hatch** (#105): the adoption story is fish-grade defaults + bash paste-compat + the native stack; a switcher's must-have plugin shouldn't block the move, but the .zshrc pile is what people are fleeing. No compsys emulation, no zle shims beyond the trivial, no zsh dialect on the critical path.
- **Tier 2 — native gRPC plugins**: resident subprocesses over hashicorp/go-plugin with a versioned protobuf API (`proto/gish/plugin/v1`). Completion providers, prompt segments, history backends. This tier is the differentiator: plugins get a real contract instead of poking shell internals, and can be written in any language. Precedent: gitstatusd and carapace already prove out-of-process is how fast shell tooling works.

Non-negotiable latency rule for tier 2: every host→plugin call carries a deadline; a slow plugin degrades (stale segment, missing completions), it never blocks a keystroke or the prompt.

**Status: interactive core in progress (M2).** Scripting runs on `mvdan.cc/sh` (POSIX/bash parse + interp). Interactive terminals get the raw-mode line editor (`internal/editor`): emacs keymap, kill ring, undo, grapheme-aware multi-line editing, diff-based inline rendering, and byte-level type-ahead preservation across commands. Signal posture is in place (#3): the interactive shell survives SIGINT/SIGQUIT — Ctrl-C interrupts the foreground command (children via the kernel, builtin loops via context cancellation) and never the shell. History is in (#4): metadata-rich JSONL at `$XDG_DATA_HOME/gish/history.jsonl` (mirrors the plugin proto's HistoryEntry), prefix-aware up/down, ctrl-r incremental search, ignorespace + consecutive-dedup + secret scrubbing (#10: gitleaks-style rules in internal/history/scrub.go — matching commands never reach disk, with a notice). Stored entries fan out asynchronously to HistoryBackend plugins (fire-and-forget, deadline-bounded). Startup config is in (#6): the rc file (`$GISH_RC` → `$XDG_CONFIG_HOME/gish/gishrc` → `~/.gishrc`, first hit wins) runs in the session runner. `GISH_PROMPT`/`GISH_PROMPT_CONT` remain the manual override but are **no longer a separate pipeline** (#109): they are the `literal` theme inside the theme engine, so plain/p10k/starship/plugin/manual all render through one dispatch (`themeName` resolves precedence: manual > NO_COLOR-forced plain > GISH_THEME). The escape set is frozen and zsh-spelled — `%n`/`%u`, `%m`/`%h`, `%~`/`%w`, `%W`, `%d`, `%?`, `%#`, `%p{id}`, `%%` — with unknown escapes passing through. Job control is in (#5): each command line runs in its own process group with terminal handoff (`SysProcAttr.Foreground`, race-free), stops observed via `Wait4(WUNTRACED)`, and jobs/fg/bg as gish builtins routed through the CallHandler rewrite. **The M2 interactive core is complete.** M3 has begun: the plugin host (#7) is live — discovery from `$XDG_DATA_HOME/gish/plugins`, lazy resident launch, Describe-driven capability wiring, deadline constants from docs/plugins.md, crash healing with exponential backoff, and the `plugins` builtin for inspection. Plugin configuration is a **declarative manifest, not ice modifiers** (#108, internal/manifest + internal/repl/plugincmd.go): `$XDG_CONFIG_HOME/gish/plugins.toml` holds source/kind/pin/lazy entries, `plugin add|remove|pin|enable|disable|update` edits it (config-style: writes the file *and* takes effect), lazy entries defer through a CallHandler that sources the payload on first use of their trigger command, and `zi migrate` imports existing installs. The zi engine remains the implementation and `zi` still works behind a one-time deprecation notice; ice syntax is documented only for migration. The zi plugin manager (#23) is in: zi-go's engine ported to internal/plugmgr behind the replaceable Manager contract, driven by the `zi` builtin through the CallHandler — a load becomes `source <payload>` in the live shell (the upstream zsh shim is gone). Existing Zi syntax and ~/.zi-go layouts carry over. The flagship gish-git plugin (#8) ships in cmd/gish-git — a gitstatusd-class prompt segment (fsnotify invalidation, background refresh, stale-on-miss) consumed via the `%p{git}` prompt escape. Completion v1 (#32, M4) is in: Tab completes command names (PATH+builtins+functions, cached) and file paths (core providers in internal/complete), merges CompletionProvider plugins behind the 80ms budget, inserts escaped values (host owns quoting), and lists candidates below the edit line when ambiguous. The carapace bridge (#9, cmd/gish-carapace) plugs ~1,000 CLIs into that socket by shelling out to the user's carapace binary (`export` JSON), guarded by its supported-command list — no carapace installed means empty results, never errors. CommandProvider (#11) is live: plugins register commands (reserved builtin names rejected, PATH shadowed, streamed I/O, no raw-TTY handover in v1) routed by an mtime-cached command index — warm sessions know plugin commands without launching anything. Startup is guarded (#37): ~6ms warm to first prompt, CI regression gate in cmd/gish/startup_test.go (`make bench-startup`); prompt-segment discovery warms in the background and the first render waits only within its 50ms budget — plugin launches never block first paint. Fish parity is in (#38/#39): parser-driven syntax highlighting (real parse tree — unknown commands red, strings/expansions/comments styled, first-word fallback on mid-edit parse errors) and history ghost-text autosuggestions (Right/End accepts), both skipped under NO_COLOR/dumb terminals. M5 quick wins: live cross-session history (#40: lookups reload the file tail, own-session entries skipped, partial-line tolerant), Damerau did-you-mean suggestions on command-not-found (#42), native brew shellenv at startup (#44: stat/string only, no subprocess), and first-class starship (#45: GISH_THEME=starship renders via the binary, budgeted + stale fallback, hint-never-autoswitch). Login-shell correctness (#41): -l or a dash-prefixed argv[0] sources /etc/profile then ~/.gish_profile|~/.profile ($GISH_PROFILE overrides for tests); the -c/script path is POSIX-clean and prompt-free, pinned by the compat suite in cmd/gish/compat_test.go. The prompt starts naked: the out-of-box default is the stock zsh/bash shape (`user@host dir %`), and themes are explicit opt-ins — GISH_THEME=p10k selects the **native powerlevel10k port** (internal/p10k, see below), GISH_THEME=gish the original segment-knob theme (#26, internal/repl/theme.go: smart path, git segment, .tool-versions pins, jobs/duration/exit — GISH_THEME_* configures this one), GISH_THEME=starship the starship renderer, and any manual GISH_PROMPT always wins; NO_COLOR and TERM=dumb force naked regardless. **The p10k theme is a port of powerlevel10k's behavior into Go, never a zsh shim** (internal/p10k, docs/p10k.md): configuration is modeled the way upstream models it — a flat parameter namespace resolved through the same three-step fallback chain (SEGMENT_STATE_KEY → SEGMENT_KEY → KEY) — which is what lets the six presets (lean, classic, rainbow, pure, lean-8colors, robbyrussell) be *data* over one layout algorithm rather than six renderers. Segments return color as `Span`s rather than pre-escaped strings, because a segment that bakes in its own reset also clears the background beneath it (that is how a powerline preset gets holes in its ribbon). ~50 segments are implemented and **none of them fork**: version managers read their pin files, kubecontext reads one top-level YAML scalar by hand, and a per-render memo backs the directory walk so twelve segments share one walk — that rule is where the speed comes from, and the unimplemented segments are exactly the ones needing a subprocess or a network call (battery, ram, load, public_ip, taskwarrior, the `*_version` family). Config layers preset → `$XDG_CONFIG_HOME/gish/p10k.conf` (mtime-cached, so edits land on the next prompt) → `POWERLEVEL9K_*` set in the session. The `p10k` builtin is the surface: `configure` (huh wizard, asks the font question rather than sniffing it, writes a complete resolved config), `import` (the **only** place in the codebase that reads zsh — offline, once; takes 304/310 settings from a real 1720-line .p10k.zsh and reports by name the ones whose value is shell code, like the stock `my_git_formatter`), `show`, `preset`, `list`. Transient prompt is in (editor `Config.Transient` swaps the prompt for the final render); `same-dir` necessarily inverts upstream's rule since the trim happens before the command runs. **Instant prompt is deliberately not implemented**: gish resolves a full p10k prompt in ~7ms (cmd/gish/startup_p10k_test.go gates it), the same as the naked prompt, so there is nothing to cache ahead of it — the setting is accepted and `p10k show` explains it. Measured head-to-head in docs/bench.md: gish 5.9ms vs zsh+powerlevel10k 87.3ms to first prompt. cmd/gish-p10k serves the same engine over the tier-2 ThemeProvider contract as `p10k-<preset>` — #30's first real implementation, live round trip at 129µs — but the shell itself renders in-process, since its own prompt should not pay a round trip. OSC 133 semantic marks ship (#99 stage 1, internal/repl/semantic.go): every command emits prompt-start/prompt-end/output-start/done-with-status, so kitty, WezTerm, Ghostty, iTerm2, and VS Code give gish users scroll-to-prompt, select-output, and click-to-rerun *today* without gish becoming a terminal; doctor names the terminal and what it supports, GISH_SEMANTIC_MARKS=off opts out. The A/B marks wrap the prompt *string* rather than the render call — the renderer already treats escapes as zero-width and atomic, so they survive redraws, wrapping, and multi-line prompts. Output capture is deliberately **not** shipped: a foreground child gets the real terminal fds and its process group owns the terminal, so capture means a pipe (breaks isatty — kills paging and color) or a PTY (preserves behavior but must take over window-size and signal forwarding around a race-sensitive handoff). docs/blocks.md records the decision — PTY, opt-in, foreground-only — and the staged plan, so it is not re-litigated. `gish ssh` is in (#98, internal/remote + cmd/gish/ssh.go): the answer to the most-cited blocker to switching shells — the box you only have ssh to. One multiplexed ssh connection (ControlMaster, one auth), one 2s-bounded probe (`uname -sm`, a writable *and executable* dir — /tmp is noexec on CIS-hardened hosts, so the probe writes a script, chmods it, and runs it — hash tool, already-present check), then `cat > file.partial` (not scp/sftp, which hardened boxes disable; ssh -C does the compression so no remote gzip is needed), verify sha256, rename, and `ssh -t host 'exec <path> --remote-session --rc <path>'`. The binary is content-addressed, which buys free upgrades, truncation detection, and safety from a co-tenant on a shared box — the threat model is explicitly *not* a rooted host. **Never installs**: no chsh, no remote dotfiles, no daemon, and `ssh` is never shadowed (auto-hijacking it drops executables on servers people don't own — FIM alerts, change control). Config travels as a hash-named 0600 rc of GISH_* display settings passed *as a path* (argv is world-readable via /proc; SendEnv is restricted by AcceptEnv); history, credentials, and plugins do not travel. Cross-platform builds are **not downloaded** (#112's line): $XDG_CACHE_HOME/gish/remote-bin/<os>-<arch>/gish, with the exact `go build` command in the error. Every failure lands in plain ssh with one line on stderr. `config ssh.bring ask|always|never` (ask once per host, remembered in ssh-trust state that resets to ask when corrupt), `--ephemeral`, `--forget`, `--uninstall`, and a README dropped beside the binary so a sysadmin shrugs instead of filing a ticket. The Transport interface (Run/Interactive/Close) is load-bearing twice over: kubectl/docker exec are the same problem, and the local `sh` transport makes the whole failure matrix testable with no ssh and no network. Terminfo is deliberately not pushed — internal/term is escape-sequence based end to end. docs/ssh.md is the reference; OSC-52 clipboard split to #140. The selection primitive is in (#100, internal/ui/fuzzy.go + picker.go): one bubbletea picker with an in-tree fzf-shaped fuzzy matcher (subsequence, scoring consecutive runs / word starts / early matches), reused by Ctrl-R and the `pick` builtin. Ctrl-R is now a full-screen picker over history showing cwd, age, duration, and exit status per row (history.RecentEntries supplies the metadata the JSONL store always had), falling back to the incremental search when the terminal cannot host a TUI — including when it reports an unusable size, which would otherwise spin the renderer. `… | pick [-m]` is the same widget as a pipeline primitive, reading keys from /dev/tty since stdin is the candidate list. The editor's external-edit machinery generalized into a **handover**: any full-screen program (an $EDITOR, a picker) gets raw mode suspended and the decoder stopped, then resumed — that seam is how future full-screen surfaces should take the terminal. Muscle-memory parity is in (#96, internal/editor/readline.go + internal/repl/histexpand.go): the readline commands whose absence has documented cases of people abandoning a shell — Alt-. / Alt-_ yank-last-arg with repeat-to-cycle (wrapping at the oldest, replacing the prior insertion), Alt-# comment-and-accept, Ctrl-T transpose, Ctrl-O operate-and-get-next (queues the next history entry into the following prompt via editor.Preload), and Ctrl-X Ctrl-E edit-in-$EDITOR (ReadCommand splits into decoder sessions so raw mode and the decoder are suspended around the child — VISUAL/EDITOR from the session first, then the environment). History expansion runs on the raw interactive line before parsing: !!, !$, !^, !:N, !:N-M, !prefix, ^old^new, echoed bash-style, never firing inside single quotes or on `! `/`!=`/`!(`. Tab expands $VAR/${VAR}/~ under the cursor (the zsh behavior fish converts miss). Ctrl-R cycling and Ctrl-G restore-line already matched readline. Numeric arguments (Alt-4 Ctrl-D) are the one deliberate gap, split to #116. Footgun diagnostics (#46, internal/repl/lint.go): the parsed buffer is checked per keystroke — unquoted expansion under destructive commands, cd sequenced (not &&-chained) before a destructive command, unquoted expansion in [ ], useless cat, self-truncating redirects — and warnings render as dim caution lines below the edit line via the editor's Diagnose hook; multi-line buffers additionally get a budget-bounded shellcheck pass on Enter when installed. Advisory only, never blocking; GISH_LINT=on|native|off. The `config` command (internal/repl/config.go, groundwork for #28) sets and persists settings in one step — `config theme starship` validates the value, rewrites the assignment in the rc file (creating the XDG one when none exists), and goes live via a CallHandler rewrite to `eval`; settings: theme (plain|p10k|starship), lint (on|native|off), prompt (free-form). Theme engine v2's first slice (#28): the themed first line is segment-driven — GISH_THEME_SEGMENTS picks and orders segments (built-ins dir git pins jobs duration exit, plus any %p{id} plugin segment by its id), GISH_THEME_COLOR_<ID> overrides a segment's color (named palette or raw SGR params), and config grew dotted keys: `config theme.git off` toggles one segment (built-ins re-slot in default order, plugin ids append), `config theme.segments 'dir git exit'` sets the list, `config theme.color.dir cyan` overrides (`default` clears), `config theme.lines 1` drops the two-line frame for an inline arrow, `config theme.sep powerline` swaps the two-space separator for a dim nerd-font chevron; bad values degrade to defaults, never break the prompt. `config theme` on a terminal is the p10k-configure-style wizard (internal/repl/wizard.go): ask each knob with Enter-keeps-current, show the powerline glyph and let the human judge the font (ask-don't-detect), preview the chosen layout, and persist only on the final confirmation — one rc write per changed variable, one eval for the live assignments; piped stdin keeps the plain show so scripts never hang. Right prompt (#28): GISH_THEME_RPROMPT holds right-side segment ids (same vocabulary as the left, plus the `time` built-in that lives right by convention), rendered by the editor one column short of the right edge, zsh-style — it hides whenever the typed line would reach it and never wraps; `config theme.rprompt 'time'` sets it, empty clears, manual GISH_PROMPT/plain/starship/NO_COLOR all mean no right prompt. Rounding out #28: `config theme.frame off` keeps two lines but drops the ╭─/╰─ corners (bare arrow — the spaceship shape), and `config theme.preset spaceship|p10k` applies a whole look from the same knobs — each preset writes the full variable set (theme, segments, rprompt, lines, sep, frame, section colors) so switching never leaves a stale knob behind; the wizard asks the frame question on the two-line path. Themes are pluggable (#30): the v1 protos grew a ThemeProvider service (theme.proto — Themes enumeration, RenderPrompt over a full PromptContext, rprompt in the response) with CAPABILITY_THEME and host wiring; GISH_THEME resolves a built-in name first (plain/p10k/starship, now peers in a builtinThemes registry behind one render-the-triple signature — reserved, unclaimable by plugins), else a discovered plugin theme by declared name (internal/repl/themeplugin.go: background warm-up, budget-bounded RenderPrompt, stale prompt-set fallback), else the native p10k-class theme — an asked-for-but-unserved theme never silently goes naked, and doctor says why. EnvProvider is live (#12, env.proto + internal/repl/envdiff.go): on directory change an env plugin proposes a direnv-class diff {for_dir, set, unset}; the trust model is host-enforced — nothing applies without `trust allow`, which records (plugin, for_dir, diff-hash) in $XDG_DATA_HOME/gish/env-trust.json (internal/envtrust, write-then-rename, corrupt file disables the feature rather than resetting trust); a changed diff re-pends with a fresh notice (edit-reprompts), deny-listed vars (LD_*/DYLD_*, IFS, ENV/BASH_ENV, GISH_*) are stripped before a proposal exists, PATH is settable only through the visible allow flow, requests carry the allowlisted env subset, for_dir must be cwd or an ancestor, and applied diffs snapshot every touched variable and revert when the shell leaves the subtree; `trust` / `trust allow` / `trust revoke [dir]` is the user surface (CallHandler builtin), EnvDiff is budget-bounded at 100ms (miss = retry next change), and doctor checks the trust file. Native sandboxing is in (#21, internal/sandbox): least-privilege exec on the shell's own exec path — a sandboxed command is rewritten to re-exec gish in a private mode (`gish __sandbox-exec <policy-json> -- cmd`) whose child filters env per policy then applies platform enforcement (macOS Seatbelt via sandbox-exec, Linux Landlock best-effort by kernel ABI; Windows deferred to #47) and execs the real command, so job control sees an ordinary child. Profiles: readonly (write only the resolved TMPDIR + /dev), workspace (+cwd), no-network (TCP denied), isolated (readonly + no net + allowlisted env — the filtered-env invariant applied to exec). Surface: the `sandbox [--profile p] -- cmd` CallHandler rewrite (default workspace) and `gish --sandbox <profile>` wrapping every external command via exec middleware (after builtins/plugin-commands/not-found, before job control); a sandboxed session refuses per-command profiles (platform sandboxes don't nest; escalation waits for #34's approval gates); doctor reports the enforcement ceiling. The policy schema is what #20 will tag AI-composed commands with. Native tool-version switching v1 (#77, internal/tools + internal/repl/tools.go): on directory change the nearest .tool-versions (walk-up, home-file global fallback) resolves against the asdf install tree ($ASDF_DATA_DIR, default ~/.asdf) — bin-dir heuristic covers both plugin layouts (bin/ and */bin, e.g. golang's go/bin), fallback versions and `system` and `path:` pins per asdf semantics — and PATH is rebuilt: resolved dirs prepend, previous prepends drop out, user mid-session PATH edits survive. No shims, no hooks, no subprocess on cd, and no trust prompt (pins only select among installed versions — contrast #12, where plugins can propose arbitrary values). Runs before EnvProvider plugins in the prompt loop; pinned-but-not-installed warns once per file+pin; GISH_TOOLS=off / `config tools off` disables; doctor reports what resolved and names the asdf install fix. #77 v2 is in: resolution reads both install trees (asdf, then mise via MISE_DATA_DIR/XDG_DATA_HOME), the pins prompt segment shows install truth (uninstalled pin → ✗ suffix, cache cleared on tool edits), and the `tool` builtin (internal/repl/toolcmd.go, CallHandler like config) is the user surface — `tool` (pins in scope with active/NOT INSTALLED), `tool list <name>` (installed versions, active starred), `tool pin`/`tool global` (SetPin rewrites the nearest/.home .tool-versions, live immediately via toolsMgr invalidation), `tool install <name> <ver>` (rewrites to `asdf install` for plugin-ecosystem compat). **Installing is delegated, not native (#112)**: `tool install … --from owner/repo` prints the equivalent ubi/mise/asdf one-liner and installs nothing — the scope line is *native for the keystroke, prompt, and cd path; delegate everything else*, and a release downloader carries package-manager obligations gish should not own. plugmgr/ghr stays (plugin installation is gish's own artifact class) and keeps the .tar.xz support that work added. AI-native integration is in (#20, ai.proto + internal/repl/ai.go + cmd/gish-claude): model access is a tier-2 AIProvider (Compose streams best-first command candidates; Explain answers why-did-that-fail), never a hardcoded vendor — gish-claude is the reference provider driving the user's claude CLI, GISH_AI_PROVIDER selects among several. The shell surface is the `??` line prefix (query → candidate lands in the next editor buffer via editor.Preload, wrapped by default in a visible `sandbox --profile workspace --` invocation the user can edit away — GISH_AI_SANDBOX tunes it, shell-state commands like cd are never wrapped) and the `explain` builtin (CallHandler). Correctness rules are structural: explicitly invoked only; preview-before-execute always (AI output never auto-executes); scrub-safe context by construction — recent commands come from the history store, which never records secret-bearing commands (#10, new Store.Recent), env is the allowlist, and nothing else leaves the machine. Human-scale AITimeout (90s), Ctrl-C cancels the model call. The agent (#34, internal/repl/agent.go + AIProvider.Plan): `agent "<task>"` is intercepted in the loop like ?? — the provider returns a step spec (plugins never hold an exec channel; the shell owns orchestration), the plan renders and saves as an artifact under $XDG_DATA_HOME/gish/agent/ with outcomes appended per step, and nothing executes until approved: [a]ll mode still gates destructive steps individually (provider flag OR the shell's own parse via the lint destructive set — unparsable gates), [s]tep gates everything, escalating out of the sandbox is its own explicit answer ([!]), a failing step halts the plan, and steps run through the real exec path (BeginLine/runInterruptible/EndLine) wrapped in the visible sandbox invocation (GISH_AGENT_SANDBOX, default workspace). Kiro's hooks idea split to its own ShellEvents design issue. **The agent builtin is frozen and experimental (#111)**: gish's position is to *host* other people's agents (sandbox profiles on the exec path, gated env, secret-free history) rather than to be one — `??` and `explain` are the advertised AI surface. The code stays because execution belongs to the shell (a plugin may never hold an exec channel, so orchestration cannot move behind the plugin boundary without weakening that invariant), but it is unadvertised and gets no further investment; do not extend it without new demand data. gish-aws (#79, cmd/gish-aws) is the first many-capability vendor plugin (the gish-git pattern widened): the %p{aws} prompt segment (profile@region + SSO token expiry, from ~/.aws config structure and token *metadata* only — never credential values, never an AWS call on the prompt path, mtime-cached), --profile/--region completion (profiles from the user's own config; carapace keeps subcommand breadth), per-directory AWS_PROFILE/AWS_REGION proposals from a walk-up .aws-profile file through the #12 trust flow, and aws-whoami (5-minute TTL) / aws-login commands. To feed it, prompt.proto grew additive per-segment env requests: SegmentDescriptor.env_keys declares what a segment wants (AWS_PROFILE etc.), RenderRequest.env carries only the declared keys that survive the host deny policy (envDenied + secret-shaped names — repl requestedEnv), so segments see the live session value, not plugin-launch-time env. Native z is in (#94, internal/dirjump + internal/repl/jump.go): zoxide-class frecency jumping with the shell as the tracking point — the loop notes directory changes (zero prompt hooks), a fresh index bootstraps from the history store's recorded cwds (day one knows where the user works), and matching follows zoxide's rules (terms in path order, last term biased to the final component; frecency = visits × recency bucket 4x/2x/0.5x/0.25x). `z terms` rewrites to a real cd; bare `z` / `z -i` opens the #90 chooser (headless degrades to the ranked list); `z -l` lists scores; the index lives at $XDG_DATA_HOME/gish/dirs.json (atomic save on exit, dead dirs pruned, capped at 1000, corrupt index resets — it is derived state, unlike env-trust); GISH_JUMP=off / `config jump off` opts out. The doctor command (#67, internal/repl/doctor.go, a CallHandler builtin like config): checks the moving parts — rc file resolves and parses, GISH_THEME_* values valid (starship/shellcheck binaries present when selected), history file writable with a parsable tail, plugin-dir entries executable, TERM/NO_COLOR degradations explained — each line ✔/⚠/✘ with the exact fix command; exit 1 only on ✘, advisory-only (never mutates), and reachable from a working shell via `gish -c doctor`. ## Architecture invariants

Read these before touching `pluginhost` or the protos.

- **`proto/gish/plugin/v1` is frozen-additive**: new fields and new RPCs are fine; renames, type changes, and removals are not. Breaking changes mean a `v2` package and a `Handshake.ProtocolVersion` bump.
- **Deadlines are the host's job**: `pluginhost` attaches a deadline to every outbound call (prompt segments default to a 50ms budget; segments can declare their own via `SegmentDescriptor.budget_ms`). Plugin responses that miss the deadline are dropped or served stale — never awaited.
- **Plugins are resident**: launched lazily on first use, kept alive for the session. Never spawn-per-call.
- **Environment is allowlisted**: completion/prompt requests carry a filtered env map, never the full environment.
- **The shell owns history**: a HistoryBackend plugin observes and serves search; the local history file works with zero plugins installed.
- **Windows is a target, not a port — sequenced to v1.x (#110)**: keep the invariants that make the port a resume rather than a restart (no unix-socket-only assumptions — go-plugin falls back to TCP loopback; PATHEXT-aware executable checks; USERPROFILE beside HOME in tests; the windows-latest CI job gates every PR). Native interactive work (ConPTY, job objects, installer — #87/#89) is deliberately paused until after a v1 that wins on macOS/Linux; WSL2 is the documented Windows story meanwhile.

- **Linter**: golangci-lint v2, config in `.golangci.yml` (`pkg/pluginapi` is excluded — it's generated)
- **Imports**: grouped by goimports with local prefix `github.com/blairham/gish` — local imports get their own trailing group
- **Generated code**: `pkg/pluginapi` comes from `make proto` only; regenerate rather than edit, and commit the output so builds don't require protoc
- **Exit codes**: `errors.As` with `interp.ExitStatus` distinguishes a script's exit status (propagated as the process exit code) from real gish errors (stderr + exit 1)
- **Commits/PRs**: no AI-attribution trailers — do not add `Co-Authored-By: Claude`, "Generated with Claude Code", or similar to commit messages or PR bodies

## Bash compatibility

`docs/compat.md` is the published scoreboard (#101): a curated corpus of
real-world snippets (`internal/compat`) run **differentially** — the same
script through the machine's real bash and through `gish -c`, comparing
combined output and exit status. bash is the oracle; nothing encodes what
we think bash ought to do. `make compat` regenerates the doc from a live
run; `make compat-check` is the CI gate that refuses a lower pass count
than the doc records. The corpus is meant to grow, so the percentage can
fall without a regression — that is the point. Substrate gaps go upstream
to mvdan/sh (#119); shell identity (`BASH_VERSION` and tool init hooks) is
an open decision (#120), not a bug.

## Launch artifacts

`docs/announcement.md` is the launch playbook (#106): the one-idea
positioning, the rules earned from other projects' scar tissue (never
headline gRPC, trust stance bolded up front, never require `chsh`,
concede the ssh objection, be in the thread), the artifact checklist with
honest state, and what we will *not* claim. `docs/porting.md` is the
muscle-memory guide for arrivals from bash/zsh. The README leads with the
one idea and links the measured artifacts — keep those three, plus
`docs/compat.md` and `docs/bench.md`, consistent with each other; a
README claim without a doc behind it is exactly what the playbook exists
to prevent.

## Benchmarks

`docs/bench.md` is the published performance claim (#102), generated by
`make bench` from `internal/bench`. Startup: every shell launched under a
real pty with its prompt overridden to one shared marker, so "first
prompt" is the same event everywhere; medians *and* best-of are printed,
missing shells are reported rather than dropped, and each row states what
it includes. Keystroke latency is measured end to end — byte into the pty,
clock stops when the repaint comes out — so decode, highlight, suggestion
lookup, lint, and render are all inside the number; that is the answer to
"is there RPC in the keystroke path?". Timing is never a CI gate (a loaded
runner would fail an honest shell); #37's budget test remains the
gish-vs-gish guard. Two harness rules learned the hard way: `SetReadDeadline`
is unsupported on ptys, so pty reads must be a goroutine plus select, and
benchmarks must start in a neutral cwd or they measure the measuring
directory. Both rules bind `cmd/gish/startup_test.go` too: a bare pty
read there once turned a single missed prompt marker into a 10-minute CI
timeout with no evidence, so the gate reads via goroutine plus select and
fails with the bytes it did see. Its prompt marker is the OSC 133;B mark
(#99) — the exact "prompt ended" signal — with the glyph markers kept as
the `GISH_SEMANTIC_MARKS=off` fallback.

## Key Dependencies

- `mvdan.cc/sh/v3` — POSIX/bash parser and interpreter; the scripting substrate the zsh dialect grows on top of
- `hashicorp/go-plugin` — tier-2 plugin transport (same architecture as the cloudctl/understudy/chaos-lab tools)
- `google.golang.org/grpc` + `protobuf` — the plugin contract
- `charmbracelet/ultraviolet` — input **decoding only** (`EventDecoder`), behind `internal/term`; gish owns the read loop
- `golang.org/x/term` — raw-mode entry/restore
- `rivo/uniseg` — grapheme clusters and display widths for the editor/renderer

## Testing

- `go test -race ./...`; the REPL core is tested through `repl.RunReader` with `interp.StdIO` redirection — no real terminal needed
- Tests must never touch real user state (home directory, real shell rc files, real history). Use `t.TempDir()` + `t.Setenv`
- Plugin host integration tests (spawning a real plugin binary over go-plugin) land with the first dispatch path; keep them hermetic by building the fixture plugin from `testdata` at test time
